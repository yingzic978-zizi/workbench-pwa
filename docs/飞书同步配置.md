# 飞书多维表格 → 工作台 灵感板块 同步配置指南

> 本配置完成后：**你飞书「01_爆款素材库」里新增/改动了"是否值得复用 = 强复用"的记录，工作台灵感板块才会更新**（不再是每天定时轮询）。点击灵感卡片"查看来源"会跳真实视频。

---

## 同步触发方式（二选一）

| 方案 | 触发时机 | 麻烦程度 |
|---|---|---|
| **A. 飞书表自动化（推荐）** | 你在飞书表新增/改记录 → 自动触发同步 | 配一次，之后全自动 |
| **B. 手动点 Run workflow** | 你改完表 → 去 GitHub Actions 点一下 | 每次手动，但 100% 稳 |

> 建议 A 为主、B 兜底（万一哪天自动化没触发，手动点一下就行）。

---

## 总览（一次性配置，约 10-15 分钟）

```
建飞书自建应用（5分钟）
    ↓
添加权限 + 授权 base（5分钟）
    ↓
配置 GitHub Secrets（1分钟）
    ↓
配置飞书表自动化 OR 手动 Run workflow 验证（1分钟）
    ↓
以后「改表即同步」✅
```

## 第一步：在飞书开放平台建自建应用

1. 打开 https://open.feishu.cn/app → 用飞书账号登录
2. 点 **创建企业自建应用**
3. 填：
   - 应用名称：**工作台灵感同步**（或随便起）
   - 应用描述：随便
4. 创建后进入应用详情页

---

## 第二步：添加权限 + 启用应用可见范围

1. 进入应用 → 左侧 **权限管理**
2. 搜索 `bitable` → 找到 **`bitable:app:readonly`**（读取多维表格内容）→ 勾上
3. 进入 **版本管理与发布** → 创建版本 → 申请发布
   - 选择「仅本企业可见」即可
   - 管理员审批通过后，应用才真正可用
4. 进入 **基础信息** → 复制 **App ID** 和 **App Secret**（马上要用）

---

## 第三步：把应用添加到多维表格的"协作者"

这一步关键，**没做的话脚本会报权限错误**。

1. 打开你的多维表格：`https://my.feishu.cn/base/N7rqbZvpeahjsksLfQDcqNPcnac`
2. 右上角 **分享** → **添加协作者**
3. 搜索你的 app 名字（如"工作台灵感同步"）
4. 权限选 **可阅读**
5. 确认

---

## 第四步：配置 GitHub Secrets

1. 打开你的仓库：`github.com/yingzic978-zizi/workbench-pwa`
2. **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
3. 添加两个：
   - Name: `FEISHU_APP_ID` / Value: 你的 App ID
   - Name: `FEISHU_APP_SECRET` / Value: 你的 App Secret
4. 保存

---

## 第五步（方案 A，推荐）：配置飞书表自动化，改表即同步

> 原理：飞书多维表自带「自动化」功能，当记录新增/更新时，自动发一个 HTTP 请求触发 GitHub Actions 跑同步脚本。

### 5-A-1 先准备一个能触发 GitHub Action 的 Token（PAT）

1. 打开 GitHub → 右上角头像 → **Settings** → 左侧 **Developer settings** → **Personal access tokens** → **Tokens (classic)**
2. **Generate new token (classic)**
3. Note 填 `feishu-trigger`，Expiration 选 **No expiration**（或按你习惯）
4. 勾选 **`repo`**（含 `public_repo` 即可，因为仓库是 public）
5. **Generate token** → **复制那串 `ghp_...`**（只显示一次，存好）

> ⚠️ 这个 PAT 接下来会明文填进飞书自动化的配置里。因为你的多维表格是私有的、只有你和同事看，风险可控；若介意，可改用方案 B（手动点）。

### 5-A-2 在飞书表里建自动化

1. 打开你的多维表格 → 顶部/侧边找到 **自动化**（或「拓展」→「自动化」）
2. **新建自动化**，起名「同步到工作台」
3. **触发器**选 **「记录变更时」**（可勾选「新增记录时」+「记录更新时」）
4. **筛选条件**（可选，建议加）：当「是否值得复用」**等于**「强复用」——这样只有标了强复用的改动才触发，省额度
5. **操作**选 **「发送网页请求」**，按下面填：
   - 请求方法：**POST**
   - 请求地址：
     ```
     https://api.github.com/repos/yingzic978-zizi/workbench-pwa/dispatches
     ```
   - 请求头（Header）添加三条：
     | Key | Value |
     |---|---|
     | `Accept` | `application/vnd.github+json` |
     | `Authorization` | `Bearer 你刚复制的ghp_...PAT` |
     | `X-GitHub-Api-Version` | `2022-11-28` |
   - 请求体（Body，选 JSON / raw）：
     ```json
     {"event_type":"feishu-sync"}
     ```
   - 内容类型选 `application/json`
6. **保存并启用**自动化

### 5-A-3 验证

1. 在飞书表里新建一条记录，把「是否值得复用」设为「强复用」，随便填点字段
2. 等 1 分钟左右，打开 GitHub 仓库 → **Actions** 标签
3. 应看到一条新的「灵感同步（飞书多维表格）」运行记录
4. 成功的话，仓库会多一个 commit，工作台灵感页刷新就有这条了

> 若 Actions 里没出现运行记录：多半是飞书自动化 header 受限或 PAT 权限不够。此时退回**方案 B**手动触发即可，功能不受影响。

---

## 第五步（方案 B，兜底）：手动触发

不配飞书自动化也行，改完表手动点一下：

1. 仓库 → **Actions** 标签
2. 左侧选 **「灵感同步（飞书多维表格）」**
3. 右侧 **Run workflow** → 绿色按钮
4. 等 30 秒看结果：
   - ✅ 成功：日志里看到「已写入 ... 共 N 条」+ 仓库有新 commit
   - ❌ 失败：日志里看错误，常见：
     - `permission denied` → 第三步没加 app 到协作者
     - `app secret invalid` → App Secret 复制错了
     - `field not found` → 表「是否值得复用」字段名变了

---

## 第六步：日常使用

- **想加新灵感** → 飞书表新建记录 → 「是否值得复用」选「强复用」 → 自动（方案A）或手动（方案B）同步到工作台
- **想立刻同步** → 方案 A 等 1 分钟；方案 B 去 Actions 点 Run workflow
- **不再每天定时跑**，只有表真的改动才动，省 GitHub Actions 额度

## 字段映射说明

| 飞书字段 | 工作台灵感卡对应字段 |
|---|---|
| 来源平台 | platform（平台徽标） |
| 爆款速览 | title（卡片标题） |
| 视频结构拆解 + 卖点表达方式 + 我的产品改编方向 + 人工总结 | body（详情，拼接） |
| 来源账号 | source（账号名） |
| 爆点标签 / 核心卖点 / 目标人群 / 产品类别 / 视频类型 / 黄金3秒钩子类型 / 核心情绪 / 使用场景 | tags（标签） |
| 视频链接 | url（"查看来源"跳转这个） |

**只同步「是否值得复用 = 强复用」的记录**，其他记录不会出现在灵感板块。
